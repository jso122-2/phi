Yep—import hell is real at 10k files. Here’s a battle-tested, do-this-now playbook to make Python imports boring again.

0) Quick triage (10 minutes)
	1.	Kill dup envs + caches

which python; python -V
python -m site
find . -name "__pycache__" -type d -prune -exec rm -rf {} +

	2.	Print the real import path first thing in your entrypoint:

import sys, pprint; pprint.pp(sys.path[:5])

	3.	Run once with verbose import + timings to see where it stalls:

python -X importtime -vv main.py 2> import_trace.log

⸻

1) Choose ONE project layout (and stick to it)

Option A — Classic package (most stable at your scale)

repo/
  src/
    dawn/                # ← single top-level package
      __init__.py
      core/
        __init__.py
        pulse_controller.py
        sigil_engine.py
      memory/
        __init__.py
        memory_routing_system.py
      gui/
      ...
  tests/

	•	Rule: Every import is absolute: from dawn.core.pulse_controller import PulseController
	•	All dirs that contain modules must have __init__.py. No implicit namespaces.

Option B — PEP-420 namespace packages (only if you really need multi-repo splits)
	•	Omit __init__.py and let multiple dawn/ roots merge on sys.path.
	•	Caveat: Easier to get weird shadowing. If you’re already in pain—prefer Option A.

👉 If you’re unsure, pick Option A now.

⸻

2) Stop the #1 cause: shadowing & collisions

Run these from repo root:

A. Shadowing stdlib / third-party names

# files or dirs named like stdlib modules?
grep -RIl --include="*.py" -E '^(import|from) ' src | wc -l   # sanity
fd -HI --type f '^json\.py$|^logging\.py$|^typing\.py$|^asyncio\.py$|^time\.py$|^sys\.py$' src

If found, rename your files (e.g., json_utils.py)—a local json.py will nuke import json.

B. Duplicate top-level packages

fd -HI --type d '^dawn$'  # should be exactly one under src/

C. Case or platform traps (macOS/Windows case-insensitive)

git ls-files | awk '{print tolower($0)}' | sort | uniq -d

Fix any duplicates differing only by case.

⸻

3) Pin the import root (no more relative gymnastics)

Use the src layout and install in editable mode:

# pyproject.toml (minimal)
[project]
name = "dawn"
version = "0.0.0"
requires-python = ">=3.10"

[build-system]
requires = ["setuptools>=68", "wheel"]
build-backend = "setuptools.build_meta"

# in repo root
pip install -e .
PYTHONPATH=""  # ensure you’re not depending on ad-hoc paths

Now python -m dawn.main will resolve against src/dawn.

⸻

4) Enforce absolute imports only
	•	Ban from .something import x across the tree (relative imports get gnarly at 10k files).
	•	Enable a linter rule:

pip install ruff
ruff check src --select I002,F401,F403,F405
# I002 helps import sorting; F40x catches bad wildcard/unused import patterns

	•	Sort consistently:

ruff check --select I --fix src

⸻

5) Detect cycles and missing specs fast

A. Programmatic probe (paste into a temporary script):

# tools/audit_imports.py
import pkgutil, importlib, traceback
import dawn
bad = []
for m in pkgutil.walk_packages(dawn.__path__, prefix="dawn."):
    name = m.name
    try:
        importlib.import_module(name)
    except Exception as e:
        bad.append((name, repr(e)))
for name, err in bad:
    print(f"[FAIL] {name}: {err}")
print(f"\nTotal failures: {len(bad)}")

Run:

python -X importtime tools/audit_imports.py 2> importtime.log

	•	Any [FAIL] shows the exact module that blows up.
	•	Open importtime.log to see slow chains → hunt for cycles.

B. Spot import cycles with graph tooling (optional)

pip install grimp
python - <<'PY'
from grimp import build_graph
g = build_graph('dawn')
for cycle in g.find_cycles():
    print(' -> '.join(cycle))
PY

⸻

6) Standard entrypoint patterns (avoid surprises)
	•	Always launch packages with -m so relative paths behave:

python -m dawn.run_dawn_pulse_integration --gui

	•	Inside scripts that live outside the package (launchers), don’t mutate sys.path. Keep all code importable from dawn.*.

⸻

7) Keep imports lightweight to break cycles
	•	Move heavy imports into functions if only used in rare paths:

def emergency_cooldown(...):
    from dawn.core.pulse_controller import PulseController  # local import breaks cycle
    ...

	•	Split monoliths: if sigil_engine and pulse_controller import each other, extract shared types/constants into dawn/core/_types.py that both depend on (one-way arrows).

⸻

8) Verify the environment, not just the code
	•	One venv per repo; never rely on OS Python.

python -m venv .venv
source .venv/bin/activate  # or .\.venv\Scripts\Activate.ps1
pip install -e . ruff

	•	Freeze reproducibly:

pip freeze | sort > requirements.lock

⸻

9) Fast “import gate” in CI (or a local pre-push)

Run the audit on every change:

python tools/audit_imports.py
test $? -eq 0

Or with pytest:

pytest -q --maxfail=1 -k "not slow"  # plus a test that imports the package

⸻

10) Sanity checklist (what usually fixes 80% of issues)
	•	Exactly one src/dawn/ root.
	•	Every subdir that matters has __init__.py.
	•	No files named like stdlib/3rd-party modules.
	•	Editable install (pip install -e .) and launch with python -m.
	•	Absolute imports everywhere.
	•	tools/audit_imports.py passes green.
	•	find __pycache__ cleared after big refactors.
	•	No sys.path hacks in scripts.

If you get a specific error trace, paste the top 20 lines and the module name—it’ll point straight to either a cycle, a shadowed stdlib name, or a path issue.
