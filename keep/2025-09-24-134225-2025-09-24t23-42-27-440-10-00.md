Great Q. Here’s a tight, copy-pasteable setup so Claude-in-Cursor acts like a careful junior, not a chaotic refactor daemon.

1) Non-negotiable guardrails (enable/ritualize)
	•	Read-only by default: Claude never writes files directly. It must return unified diffs (patches) + tests.
	•	Allowlist / Denylist:
	•	Allow: dawn/experiments/**, docs/**, tests/**, configs/**.
	•	Deny: dawn/core/tick_engine.py, dawn/core/pulse_controller.py, dawn/core/memory/**, dawn/core/sigil_engine.py (until canary passes), any launcher in prod path.
	•	One package, absolute imports: enforce from dawn.x import Y only.
	•	No new deps, no renames: any attempt to add requirements or rename core symbols = hard fail.
	•	Diff size ceiling: ≤ 200 lines changed; else split into smaller tickets.
	•	Test-first acceptance: every patch must add/update tests that prove the change.
	•	Telemetry intact: patches must not touch event schemas or manifest without an explicit schema migration ticket.

2) Cursor “Claude Agent” system prompt (drop-in)

Paste this as the agent’s System message/preset:

ROLE: Code patch assistant for DAWN (deterministic, local, no abstractions).
YOU MUST:
	1.	Search for existing logic before proposing new code; modify in place when possible.
	2.	Respect naming and architecture: SCUP, SHI, rebloom, tracers, pulse/heat, Owl/Sigil, Memory Router. Do not rename anything.
	3.	Return unified diff only + minimal notes + new/updated tests. No prose explanations, no file writes.
	4.	Stay within allowlist paths only. Denylisted files are read-only context.
	5.	No new dependencies; no global refactors; no changing public signatures.
	6.	Keep imports absolute (from dawn...). If a cycle exists, propose moving the import inside the function (localized).
	7.	Maintain telemetry: do not alter events JSON schema, manifest keys, or logging IDs.
	8.	Patch must pass: ruff, type check, import audit, unit tests.
OUTPUT FORMAT:

	•	“NOTES:” (≤5 bullet points)
	•	“DIFF:” (unified diff)
	•	“TESTS:” (new/changed tests)
	•	“CHECKS:” (commands I should run)

3) Task template you give Claude (Cursor chat message)

Use this for every ask:

TASK: Reduce import time in dawn/core/sigil_engine.py by localizing heavy imports.
CONTEXT: See diagnostics in tools/importtime_report.md. Do not change public APIs.

CONSTRAINTS:
- Touch only: dawn/core/sigil_engine.py, tests/test_import_cost.py
- No new deps; no renames; absolute imports only.
- Keep logging/telemetry lines and event schema unchanged.

EXPECTED OUTPUT:
- NOTES: why/what you changed, risks (≤5 bullets)
- DIFF: unified diff
- TESTS: unit test proving import wall-clock decreases (threshold in test)
- CHECKS: commands to run (ruff, pyright/mypy, pytest -q, tools/audit_imports.py)

4) Patch gate you run in Cursor Terminal (copy/paste)

# static checks
ruff check .
pyright || mypy

# import sanity
python tools/audit_imports.py || exit 1

# tests
pytest -q

# quick canary (if allowed area)
python -m dawn.run --mode canary --ticks 1500 --kpi-budget '{"surge_pct": "<=baseline*0.9"}'

5) Context packing (don’t drown Claude)

Only attach the smallest set of files it truly needs:
	•	Target file(s) + their immediate imports (1 hop).
	•	Relevant tests.
	•	Any profiling/trace report for the task.
	•	Never the whole repo. Big contexts = hallucinated redesigns.

6) Review checklist (before you apply the diff)
	•	Only allowlisted paths changed, diff ≤ 200 lines.
	•	No added deps; no public API changes; no renames of core symbols.
	•	Imports remained absolute; no sys.path hacks.
	•	Telemetry untouched (events/manifest schemas).
	•	New/updated tests included and meaningful.
	•	Static checks + tests + import audit pass locally.
	•	Canary KPIs met (if applicable).
	•	Commit message cites ticket id, why, and KPIs.

7) Common ways Claude “messes up” (and fixes)
	•	Refactors whole module → enforce diff ceiling; restate scope; reject and reissue tighter task.
	•	Adds helper abstractions → Rule 2: no new abstractions. Ask for in-place edits only.
	•	Breaks imports → Demand absolute imports; if cycle, allow only localized inner imports.
	•	Touches schemas → Immediate reject; require a separate schema-migration ticket with tests + backcompat.
	•	Forgets tests → Reject; task template requires tests by design.

8) Small, safe starter tasks for Claude
	•	Write/expand tests (zero prod risk, high value).
	•	Convert relative → absolute imports in allowlisted dirs.
	•	Localize heavy imports inside hot functions to break cycles.
	•	Micro-perf: batch small loops, remove dead code (under tests).

9) Branch & commit hygiene in Cursor
	•	One task → one short-lived branch.
	•	Signed commits; include ticket id and KPI target in message.
	•	Never push green until canary passes (where relevant).

10) Pin Claude’s behavior with examples

Keep a tools/patch_examples/ folder with:
	•	A good tiny diff (imports localized + test).
	•	A bad diff (rename public symbol, schema drift).
Link these in the system prompt so Claude learns from positive/negative patterns.
