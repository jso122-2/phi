If you still want WSL fixed (do tomorrow when rested)

Right now DNS is being overwritten and the default route is fine but name resolution fails. Fix is:

A) Fix your Windows .wslconfig (remove the bad key)

Open PowerShell (not admin) and run:

notepad $env:USERPROFILE\.wslconfig

Use exactly this (and nothing else):

[wsl2]
memory=8GB
processors=6
swap=0
localhostForwarding=true
dnsTunneling=true

Save.

B) In Ubuntu, stop auto-overwriting resolv.conf

Inside WSL Ubuntu:

sudo tee /etc/wsl.conf >/dev/null <<'EOF'
[network]
generateResolvConf = false
EOF

# stop WSL and restart
exit

In PowerShell:

wsl --shutdown

C) Start Ubuntu and set DNS to your Windows adapter’s DNS

Back in Ubuntu:

# use your Windows LAN DNS; if unsure, 8.8.8.8 + 1.1.1.1 is fine
sudo rm -f /etc/resolv.conf
printf "nameserver 8.8.8.8\nnameserver 1.1.1.1\n" | sudo tee /etc/resolv.conf

# test
ping -c3 8.8.8.8
ping -c3 google.com

If pings work, proceed with conda + training as you did before.

⸻

Why this happened
	•	That “Unknown key ‘network.generateResolvConf’” means the Windows .wslconfig had an invalid stanza. WSL then fell back to generating resolv.conf from Windows, which in your setup pointed at 10.255.255.254 (often from ISP/router/VPN), causing resolution failures inside WSL.
	•	By stopping auto-generation and writing a known‐good resolv.conf, DNS stabilizes.
